# 프롬레코드 콘텐츠 관리자

관리자 주소: https://minji5996-creator.github.io/prom-record/admin/content.html

사이트 맨 아래의 **콘텐츠 관리**에서도 열 수 있습니다. 기존 문의 관리에 등록된 관리자 계정으로 로그인합니다. 관리자 등록 여부는 기존 `prom_contact_admins` 목록으로 확인하며 일반 회원에게 편집 권한을 주지 않습니다. 로그인 정보는 브라우저 메모리에서만 유지되어 새로고침하면 다시 로그인합니다.

## 사용 순서

1. 회사 소개, 메인 영상, 포트폴리오, 챗봇 안내 데이터 중 수정할 메뉴를 선택합니다.
2. **초안 저장**으로 저장합니다. 이때 공개 사이트는 바뀌지 않습니다.
3. **미리보기**로 메인·회사 소개·포트폴리오와 챗봇을 확인합니다. 저장 전 내용도 미리 볼 수 있으며 실제 문의 전송과 방문 통계 수집은 차단됩니다.
4. **게시**를 누르면 공개 사이트에서 새 게시본을 읽습니다. 열린 페이지는 새로고침하거나 최대 약 1분 뒤 갱신을 기다려주세요. GitHub 재배포 없이 내용이 반영됩니다.

두 창에서 같은 초안을 수정했을 때는 오래된 수정이 다른 내용을 덮어쓰지 않도록 차단합니다. 충돌 안내가 뜨면 **JSON 백업**으로 편집 내용을 내려받은 후 **변경 취소 · 최신 초안 불러오기**를 선택해주세요.

## 관리 범위

- **회사 소개:** 상단 한 줄 소개, 회사 소개 제목·본문, 제작 분야. 회사 소개 본문은 챗봇 회사 소개 답변과 연결됩니다.
- **메인 영상:** 첫 번째 메인 작업명·영상 제목·설명·원본 링크·대표 이미지·MP4 주소. 모바일 기본 정지 이미지와 PC 무음 재생 정책은 유지됩니다.
- **포트폴리오:** 공식 참여 작업과 개인 작업 추가·수정·순서 변경·초안에서 제외. 공식 참여 작업은 메인, Work, 상세 페이지, 챗봇 카드에 반영됩니다. 새 공식 작업은 `work/project.html?id=작업ID` 상세 페이지가 자동으로 연결됩니다. 이미지에는 기존 `media/...` 경로나 공개 HTTPS 이미지 주소를 넣습니다. 새 파일 업로드 기능은 포함하지 않습니다.
- **챗봇 안내 데이터:** 답변·검색 키워드·선택 버튼·다음 안내 수정. 고급 JSON 편집에서 노드 추가도 가능합니다. 필수 시작·회사·포트폴리오·분야·일정·문의 노드는 유지합니다. 문의 노드의 폼은 삭제할 수 없습니다. 회사 소개 답변과 작업 카드는 해당 관리 탭의 데이터를 자동으로 따릅니다.
- **접수된 문의:** 기존 문의 폼과 챗봇 제작 문의를 같은 목록에서 확인하고 상태를 바꿉니다. 최근 100건을 표시하며 ‘챗봇 문의만’ 필터가 있습니다. 전체 페이지형 조회는 기존 문의 관리 `admin/inquiries.html`을 사용합니다.
- **게시 이력:** 최근 30개 게시본에서 이전 버전을 초안으로 불러와 다시 검토·게시합니다. 불러오기만으로 공개 내용이 바뀌지는 않습니다.

일반 방문자의 자유 입력 대화나 대화 이력을 새로 서버에 수집하지 않습니다. 기존 세션 문맥은 각 브라우저 `sessionStorage`에 있고, 명시적으로 전송한 제작 문의만 기존 테이블에 저장됩니다. 관리자에서 보이는 ‘챗봇 안내 데이터’는 등록한 회사 안내·FAQ·분기 데이터입니다.

## JSON 백업과 복원

**JSON 백업**으로 현재 편집 내용을 내려받을 수 있습니다. **JSON 가져오기**로 다시 편집 화면에 불러온 뒤 초안 저장·게시합니다. 가져오기만으로 서버나 사이트를 덮어쓰지 않습니다. HTML 코드, `javascript:` 링크, 범위를 벗어난 내부 경로, 존재하지 않는 분기 등은 허용하지 않습니다. 확인되지 않은 회사 실적·가격·기간은 ‘내용 입력 필요’를 유지해주세요.

## 저장 구조와 권한

- `prom_site_published`: 공개 사이트와 챗봇이 읽는 게시본.
- `prom_site_drafts`: 관리자만 읽고 수정하는 초안.
- `prom_site_revisions`: 관리자만 조회하는 게시 이력.
- `prom_contact_inquiries`: 기존 제작 문의. 새 접수함으로 복제하지 않습니다.

모든 CMS 테이블에 RLS가 적용되고 게시·저장은 기존 관리자 함수로 권한을 확인합니다. 익명 사용자는 게시본만 읽습니다. 브라우저에는 공개 publishable key만 있고 Secret/service_role 키는 없습니다. 새 권한 검증 함수는 SECURITY INVOKER입니다.

## 개발 및 배포

기존 Vinext / 정적 HTML 개발 환경을 유지합니다.

```powershell
npm run dev
npm run build
node scripts/export-github-pages.mjs
```

로컬 원본 `data/site-content.json`은 연결 장애 시 사용하는 정적 기본 안내입니다. 사이트의 실제 편집·게시본은 Supabase에 저장되며 일반 빌드로 DB 게시본을 덮어쓰지 않습니다. `scripts/install-cms.mjs`가 관리자·공개 스크립트와 버전 주소를 생성합니다. Supabase가 응답하지 않을 때는 정적 기본 내용으로 안내를 유지합니다. 정적 HTML 원본의 검색 메타데이터와 외부 공유 미리보기까지 갱신하려면 별도 빌드·배포가 필요하며, 관리자 게시만으로 GitHub 파일 자체가 수정되지는 않습니다.

```powershell
node scripts/qa-cms.mjs
node scripts/qa-chatbot.mjs outputs/github-prom-record/site
node scripts/qa-analytics.mjs
```

실제 DB 검증은 `scripts/qa-cms-db.sql`에서 관리자 저장·게시·충돌·RLS를 트랜잭션으로 검사한 뒤 롤백합니다. 운영 게시 내용과 문의를 테스트 값으로 남기지 않습니다. UI 자동 검사의 로그인·게시 응답은 가짜 서버로 격리하며 실제 관리자 비밀번호는 사용하지 않습니다.

## 기존 보안 설정 참고

보안 검사에서 CMS 테이블의 누락된 RLS는 발견되지 않았습니다. 기존 관리자 명단 테이블은 클라이언트 접근을 막기 위해 RLS 정책 없이 보호하고 있습니다. 프로젝트에는 기존 ‘유출 비밀번호 보호 비활성화’ 알림이 남아 있습니다. 이 기능의 지원 범위와 설정은 [Supabase 비밀번호 보호 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)를 참고하세요. 이번 작업에서 기존 로그인 정책은 변경하지 않았습니다.
